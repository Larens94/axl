LINGUAGGIO DI ESECUZIONE PER AGENTI · SORGENTE COMPATTO 2

Non scritto per gli esseri umani.
Creato per gli agenti.

AXL è un linguaggio general-purpose compatto e deterministico. Gli agenti generano meno token, il compiler elimina l'ambiguità e i backend trasformano lo stesso sorgente in software per qualsiasi piattaforma.

01 / LINGUAGGIO

Meno sintassi.
Più semantica.

AXL non imita linguaggi costruiti per essere letti dagli esseri umani. Usa frame numerici, campi delimitati ed espressioni RPN.

BINDING + CALCOLO10|x|#2,#3,#4,*,+|i

Binding tipizzato. La RPN elimina precedenza e parentesi.

FUNZIONE40|add|a:i,b:i|i;11|$a,$b,+;99

Firma, corpo e ritorno in un unico flusso.

IMPORTAZIONE1|m|m.axl;12|#20,#22,^m.add/2

Modulo relativo, namespace esplicito, chiamata postfissa.

MEMORIA20|k|"v"|95|3600|r;12|@k

Record AM con scope, affidabilità, TTL e sorgente.

USO GENERALE

Compatto non significa limitato.

AXL è progettato per esprimere backend, web, applicazioni native e mobili, sistemi, grafica, carichi GPU, agenti e workflow. Il sorgente resta stabile mentre evolvono i bridge di destinazione.

02 / ARCHITETTURA

Un solo sorgente.
Qualsiasi backend.

Rust è il primo runtime di basso livello, non un limite del linguaggio. AX-HIR, AX-MIR e ABI versionate separano semantica e piattaforma.

01Compact Source 2opcode · RPN · canonico
02Parser + tipifrontend deterministico
03AX-HIR → AX-MIRsemantica tipizzata · CFG · effetti
Rust / Nativoserver · CLI · sistema
VMportabile · isolata
WASM / WASIbrowser · edge
Bridge di piattaformamobile · GPU · SO · futuro
Contratto dei bridge

Ogni bridge dichiara ABI, tipi, effetti, capability, target, cancellazione ed errori. Nessun provider o sistema operativo entra nella grammatica.

03 / ESECUZIONE

Potenza, con limiti.

Un linguaggio per agenti deve poter fare qualsiasi cosa senza ricevere implicitamente accesso a tutto.

01

Negazione predefinita

Tool e bridge esistono solo quando l'host li registra e l'agente li riceve.

02

Chiusura sicura

Solo un'approvazione booleana esatta autorizza gli effetti sensibili.

03

Memoria con scope

AM conserva valori tipizzati, metadati e TTL dentro scope controllati dall'host.

04

Budget + audit

Step, valori, output, tool e memoria sono limitati; le decisioni restano osservabili.

04 / INIZIO

Esegui l'implementazione di riferimento.

L'implementazione Python fissa oggi la semantica. `pack` converte il frontend precedente nella forma compatta canonica.

$ git clone https://github.com/Larens94/axl.git
$ cd axl && python3 -m pip install .
$ axl run examples/compact.axl
$ axl pack readable.axl -o canonical.axl
$ axl run canonical.axl
$ axl compile app.axl -o app.axlir.json
$ axl exec app.axlir.json
05 / PERCORSO

Prima la semantica.
Poi le piattaforme.

Ogni fase deve chiudere il percorso dal sorgente compatto a un programma reale verificato.

  1. 01
    Fondamenta compatte

    Source 2, parser, writer canonico, IR, policy, AM, funzioni e moduli.

    funzionante
  2. 02
    Core general-purpose

    Collezioni, record, enum, result, pattern matching ed errori strutturati.

    prossimo
  3. 03
    HIR, MIR e runtime Rust

    Lowering, VM, ABI, cancellazione e conformità tra runtime.

    pianificato
  4. 04
    Nativo, WASM e bridge

    Filesystem, rete, HTTP, database, DOM, mobile, GPU e sistemi operativi.

    pianificato
  5. 05
    Ecosistema

    Pacchetti, registro, LSP, debugger, profiler e self-hosting progressivo.

    pianificato
